# News Art Direction และ Visual Storytelling

เอกสารนี้ใช้เมื่อผู้ใช้ต้องการสร้างวิดีโอนำเสนอข่าวจากข้อมูลหรือสื่อบนอินเทอร์เน็ต โดยเฉพาะข่าวอาชญากรรม ข่าวตำรวจ ข่าวเหตุการณ์ฉุกเฉิน และข่าวที่มีผู้เสียหาย ทักษะต้องทำหน้าที่เป็นระบบช่วยจัดทำแพ็กเกจข่าวจากข้อมูลที่ตรวจสอบได้ ไม่ใช่ระบบสร้างเหตุการณ์ขึ้นใหม่หรือเติมรายละเอียดที่ไม่มีหลักฐาน

## หลักการบรรณาธิการ

ความถูกต้องต้องมาก่อนความเร็วและความเร้าใจ ภาพและเสียงต้องไม่ทำให้ผู้ชมเข้าใจว่าภาพประกอบเป็นภาพจากเหตุการณ์จริงเมื่อไม่ใช่ และต้องแยกให้ชัดเจนระหว่าง `verified_event_footage`, `archive`, `illustration`, `reconstruction` และ `generic_broll` [1] [2] การปรับภาพที่ยอมรับได้ควรเป็นการปรับเชิงเทคนิค เช่น crop, resize, stabilization, color correction, denoise และ audio cleanup โดยไม่เปลี่ยนสาระของเหตุการณ์ [1] [2]

ห้ามเติมเสียงไซเรน เสียงปืน เสียงผู้คน หรือ sound effect ที่ไม่ได้เกิดขึ้นจริงเพื่อเพิ่มความตื่นเต้น ห้ามใช้ภาพตำรวจ อาวุธ รถฉุกเฉิน หรือสถานที่ทั่วไปจนทำให้ผู้ชมเข้าใจว่าเป็นภาพจากคดีนั้น และห้ามใช้ภาพบุคคลที่ไม่เกี่ยวข้องเพื่อสื่อว่ามีส่วนในอาชญากรรม [2]

> ในข่าวอาชญากรรม ให้ใช้ถ้อยคำตามสถานะที่ตรวจสอบได้ เช่น “ผู้ต้องสงสัย” หรือ “ผู้ถูกกล่าวหา” และไม่สรุปว่าเป็นผู้กระทำผิดก่อนมีคำพิพากษาหรือหลักฐานที่ยืนยันได้

## โหมด `news_story_mode`

เมื่อผู้ใช้ระบุว่าเป็นข่าว ให้สร้างไฟล์และตารางต่อไปนี้ก่อนเริ่ม render:

| ไฟล์/รายการ | หน้าที่ |
|---|---|
| `rundown.json` | ลำดับช่วงข่าว, slug, TRT, outcue และสถานะการตรวจ |
| `source-ledger.json` | URL, publisher, author, timestamp, claim ที่รองรับ, license และความน่าเชื่อถือ |
| `scene-plan.json` | script track, ภาพ, B-roll, SOT, NAT, graphic และ transition ต่อฉาก |
| `shot-list.json` | ช็อตที่ต้องใช้, บทบาทของช็อต, event/time/location match และ risk flags |
| `lower-third-plan.json` | headline, name/title, location, date/time, attribution และ safe zone |
| `graphics-plan.json` | แผนที่, timeline, chart, quote card, photo-based graphic และ source credit |
| `correction-log.json` | การแก้ไขข้อเท็จจริง การเปลี่ยนแหล่งข่าว และเวลาที่แก้ไข |

ลำดับข่าวเริ่มต้นควรเป็น `headline/lead → verified facts → context/chronology → official statement → response from affected side when available → public impact → what happens next → attribution/correction note` [3] [4] ให้แยกคำบรรยายผู้ดำเนินรายการหรือผู้สื่อข่าวออกจากเสียงสัมภาษณ์และเสียงธรรมชาติ โดยติดป้าย `TRACK`, `SOT`, `NAT`, `STANDUP`, `MOS`, `TOP`, `TAIL` ตามความเหมาะสม [3]

## Visual relevance scoring

ให้ประเมินทุกภาพและวิดีโอด้วยคะแนน 0–5 ในมิติ `event_match`, `time_match`, `location_match`, `subject_match`, `source_confidence`, `license_readiness` และ `editorial_risk` แล้วเก็บเหตุผลไว้ใน manifest ห้ามใช้ asset ที่มี `license_readiness = 0` หรือมี `editorial_risk` สูงโดยไม่มีการอนุมัติจากผู้ใช้และป้ายกำกับที่ชัดเจน

| ประเภทสื่อ | ใช้เมื่อ | ป้ายกำกับที่ต้องแสดง |
|---|---|---|
| `verified_event_footage` | มีแหล่งที่มาและตรวจสอบเหตุการณ์ เวลา หรือสถานที่ได้ | Source/วันที่ตามจริง |
| `archive` | เป็นภาพเก่าที่เกี่ยวข้องกับบุคคล สถานที่ หรือเหตุการณ์ | “ภาพแฟ้ม/ภาพเก่า” และวันที่ถ้ามี |
| `illustration` | ใช้อธิบายแนวคิดหรือบริบท ไม่ใช่ภาพเหตุการณ์ | “ภาพประกอบ” |
| `reconstruction` | จำลองลำดับเหตุการณ์จากข้อมูลที่มี โดยไม่อ้างว่าเป็นภาพจริง | “ภาพจำลองเหตุการณ์” |
| `generic_broll` | ใช้คั่นหรืออธิบายบริบทกว้าง ๆ เท่านั้น | “ภาพประกอบ” และห้ามตัดให้เหมือนภาพคดีจริง |

หากมีหลายภาพที่เหมาะสม ให้เลือกภาพที่ชัดเจนที่สุดและมีความเสี่ยงต่ำที่สุด ไม่เลือกภาพที่รุนแรงเพียงเพราะดึงความสนใจได้มากกว่า ภาพที่ไม่มีความเกี่ยวข้องเชิงเหตุการณ์ต้องไม่ถูกใช้เป็นหลักฐานโดยปริยาย [1] [2]

## ระบบจัดวางภาพและวิดีโอ

สำหรับ 16:9 ให้กำหนด safe margin ประมาณ 5% ของความกว้างและความสูง และกันพื้นที่ lower-third ในส่วนล่างของเฟรม สำหรับ 9:16 ให้ใช้ safe margin ประมาณ 8% และกันพื้นที่ด้านบน/ล่างสำหรับแพลตฟอร์มมือถือและคำบรรยาย ตัวเลขเหล่านี้เป็นค่าเริ่มต้นเชิงงานออกแบบ ต้องทดสอบกับปลายทางจริงก่อนส่งออก

| องค์ประกอบ | หลักการจัดวาง |
|---|---|
| Headline | วางใน safe zone ที่อ่านได้ทันที ใช้หนึ่งประเด็นหลัก ไม่วางทับใบหน้าหรือหลักฐานสำคัญ |
| Lower third | วางในพื้นที่คงที่ ใช้ชื่อ/ตำแหน่ง/สถานที่ตาม source ledger และไม่ทำให้ผู้ต้องสงสัยดูเหมือนถูกตัดสินแล้ว |
| ผู้ดำเนินรายการ/Avatar | ใช้บุคคลเดิมจากภาพต้นฉบับตาม `preserve_exact_person` วางด้านที่เปิดพื้นที่ให้ข้อความหรือภาพประกอบ และห้ามเปลี่ยนใบหน้า |
| B-roll | เรียงเป็น wide → medium → detail เมื่อมีสื่อรองรับจริง เพื่อให้ผู้ชมเข้าใจสถานที่และการกระทำโดยไม่สร้างข้อเท็จจริงใหม่ |
| แผนที่ | ใช้เมื่อสถานที่เป็นสาระสำคัญ ระบุทิศทาง/จุดสำคัญพร้อมแหล่งข้อมูล และห้ามเพิ่มเส้นทางที่ไม่มีหลักฐาน |
| Timeline | ใช้เวลาเรียงจากเก่าไปใหม่อย่างสม่ำเสมอ พร้อมบอก “ตามข้อมูลที่ตรวจสอบได้” เมื่อยังมีช่องว่าง |
| Chart | ใช้ข้อมูลที่มีแหล่งที่มา แกน bar chart เริ่มที่ศูนย์ และไม่ตัดช่วงเวลาใน line chart เพื่อขยายความแตกต่าง [2] |
| Captions | วางใน safe zone ไม่บังปากหรือหลักฐานสำคัญ ใช้สี/ขนาดที่ contrast สูงและคงรูปแบบตลอดทั้งเรื่อง |

ให้รักษา visual rhythm โดยสลับ establishing shot, evidence/detail shot, source graphic และ talking-avatar ตามความจำเป็นของข้อมูล ไม่เปลี่ยนช็อตถี่เพื่อเร่งอารมณ์ในข่าวอาชญากรรม และไม่ใช้การซูม/สั่น/flash เพื่อชี้นำว่าผู้ชมควรรู้สึกผิดหรือกลัว

## ข่าวอาชญากรรมและข่าวตำรวจ

ก่อน render ให้ทำ `crime_police_ethics_gate` ตรวจว่าไม่มีภาพศพ เลือด ความรุนแรง หรือใบหน้าผู้เสียหาย/ผู้เยาว์โดยไม่จำเป็น ไม่เปิดเผยที่อยู่ เบอร์โทร ป้ายทะเบียน หรือข้อมูลระบุตัวตนเกินประโยชน์สาธารณะ ไม่ใช้ภาพผู้ต้องสงสัยในลักษณะประจาน และไม่วาง headline หรือดนตรีที่ตัดสินความผิดล่วงหน้า หากจำเป็นต้องอ้างถึงภาพรุนแรง ให้ใช้มุมกว้าง เบลอ หรือภาพแทนที่ลดอันตราย พร้อมคำเตือนเนื้อหาตามความจำเป็น [1]

เมื่อข่าวมีข้อกล่าวหาหรือข้อขัดแย้ง ให้แยก “ข้อเท็จจริงที่ยืนยันแล้ว” ออกจาก “คำกล่าวอ้าง” และพยายามนำเสนอคำชี้แจงจากฝ่ายที่ได้รับผลกระทบเมื่อหาได้ [4] เก็บเวลาในการตรวจสอบ แหล่งข่าวที่ขัดแย้ง และรายการแก้ไขไว้ใน `correction-log.json`

## Quality gate สำหรับข่าว

ก่อนส่งออกต้องผ่านรายการต่อไปนี้:

| Gate | เกณฑ์ผ่าน |
|---|---|
| Source verification | ทุก claim สำคัญผูกกับแหล่งข่าวหรือหลักฐานที่ระบุได้ และไม่ใช้ snippet เป็นหลักฐานสุดท้าย |
| Context fidelity | ภาพ/วิดีโอไม่ทำให้สถานที่ เวลา หรือบุคคลถูกเข้าใจผิด |
| Identity preservation | Avatar หรือบุคคลในภาพเป็นบุคคลเดิม ไม่มี face swap หรือ identity drift |
| Graphic safety | ไม่มีภาพรุนแรงที่ไม่จำเป็น และปกป้องผู้เสียหาย/ผู้เยาว์ |
| Attribution | lower-third, quote, graphic และภาพประกอบมีที่มาและป้ายกำกับเหมาะสม |
| Audio integrity | ไม่มี sound effect ที่ทำให้เหตุการณ์ดูรุนแรงขึ้น และเสียงพูดฟังชัด |
| Layout | ข้อความไม่ล้น safe zone ไม่บังใบหน้า/หลักฐาน และอ่านได้บนอัตราส่วนเป้าหมาย |
| Correction readiness | มี source ledger และ correction log พร้อมแก้ไขได้โดยไม่ลบ provenance |

ถ้า gate ใดไม่ผ่าน ให้ตั้งสถานะ `blocked_news_context`, `blocked_identity_drift` หรือ `blocked_source_rights` ตามสาเหตุ ห้ามส่งออกเป็น final และห้ามย้ายภาพต้นฉบับไปถังขยะ
